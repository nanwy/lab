# 01: 业务操作与持久化一致性修复

**What to build:** 修复“S06场景拓扑还原差异修复专项”R01–R04。用户新增设备、保存配置或创建业务链路后，按原可达流程完成画布提交，无需再额外点击保存；部分失败可准确恢复，不重复创建业务对象。同时恢复新增网卡MAC补零和缺失数组默认行，并阻止仍被旧业务边占用的网卡再次连线。交付包含配置、业务请求、画布持久化、失败反馈与定向回归的完整闭环。优先级P1，其中R02–R04为P2；可以先于02实施，但两票没有逻辑阻塞关系。

**Blocked by:** None (can start immediately).

**Status:** complete

- [x] R01：设备创建、设备配置保存、业务链路创建成功后，按原调用链继续提交整图；不另点保存即可通过重新GET和重开验证配置引用、节点和链路一致。核对相邻编辑/删除等已知保存调用点，同一持久化差异一并修正；不扩大为每次键入或每个拖动事件的全局自动保存。
- [x] 业务失败不提交伪成功画布；业务成功而整图提交失败时保留已成功对象和草稿，准确区分两个阶段，重试只补整图提交。实际请求计数证明不重复创建、更新已成功的业务对象，且不自行删除远端对象补偿。
- [x] 显式保存仍可提交其他待保存修改。保存成功仅推进本次提交快照的基线和该批资源追踪；请求期间的新编辑继续待保存，重复点击不会重复写入。
- [x] 离页/刷新保护覆盖未保存和在途操作，不把取消请求或放弃本地修改描述为撤销已经成功的业务写入；跨实验切换不串写旧对象，真实后端的联动或清理行为不作猜测。
- [x] R02：通过设备表单新增网卡时，沿原十进制末节加一及小于10补零规则，末节01之后产生02而非2；浏览器检查显示与实际配置提交体，已有行和未知字段不被重写，不扩展成新的MAC分配算法。
- [x] R03：普通数组缺失时恢复原默认一行；ports缺少数量定义时恢复一行，有数量定义时遵循原分支，行内字段按schema默认填充。已有合法数组（包括空数组）不被无条件补行，损坏结构仍明确拒绝。
- [x] 配置默认值经实际表单显示并进入业务提交；保留engin10禁增删规则，不能以“用户自行加行”替代恢复原缺省配置。
- [x] R04：网卡选项、提交前占用校验和现有删除保护一致考虑可渲染边及原样保留的旧业务边。磁吸点无效但NIC关系有效的旧边仍阻止同一NIC再次连接，旧边与未知字段不被丢弃。
- [x] 覆盖源/目标两端、NIC索引0、未占用NIC可连、纯图边不占业务NIC以及不同NIC的合法多重连线，不因扩大关系集合而一概禁用合法连接。
- [x] 锁定、共享/只读状态不开放新业务写入口；节点模板分阶段重试、业务ID/画布UUID/模板资源ID的区别和X6无损往返不回退。
- [x] 沿用户确认的现有测试边界，先复现红灯，再以隔离浏览器验证操作→业务请求→整图请求→失败恢复→重新GET重开；配置默认值及无效磁吸点关系仅补现有纯函数回归。模拟服务不替应用自动同步draw，不新增测试框架。
- [x] 只运行新增及直接受影响的测试、最小web类型检查及改动文件lint/格式；更新实际交付与验证记录，不跑全量检查或构建，不执行未经授权的真实业务写入。
