## 精简实施约束

用户明确要求：只还原原 bundle 可达功能，尽量精简代码。四票保留业务范围，删去重复的通用验收条目与额外设计要求；不以代码行数或增加抽象作为目标。

- 直接复用现有画布、菜单、请求、Query、表单、表格和错误提示；不新建流量通用框架、插件注册、独立任务状态机或统一配置管理器。仅在实际重复时提取最小共享逻辑，不强制合并两种记录入口的组件或数据模型。
- 原入口的字段、状态、校验、确认、分页和刷新逐项还原；不增加字段兼容猜测、业务权限、额外校验、轮询、自动重试、WS 自动重连或持久化恢复。实验隐藏的回放能力仍不实现。
- 不因空命令、不可用下载等情况另造修复流程、文件预检或下载管理器；错误沿现有 API 提示处理，不把失败显示为成功。
- 保留必要的上下文隔离与本票创建的请求、连接、监听清理，避免串对象与泄漏；不把这些要求扩展为新生命周期框架，不在离页时自动停止远端业务。
- 验证围绕本次主要用户流程与少量关键契约，复用现有隔离 HTTP/WS 和浏览器设施；不要求逐字段、逐组件镜像测试，不另建协议仿真平台，不将真实采集、本机 Wireshark 联通或真实写入作为额外完成门槛。类型、lint、格式及受影响验证仍按仓库规则执行。

### 流量模拟的处理

本轮保持实验原入口不显示回放页签，不创建不可达回放功能票。通用回放能力保留为后续实际消费者的补证事项；后续切片接入时需显式核对归属，不能因此宣称 F042 的全站回放能力已完成。S08 收口时在覆盖记录说明该入口的不适用原因；若未来新增证据证明实验存在另一个可达入口，应先修正范围台账再补票。
