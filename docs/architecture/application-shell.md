- 统计及推荐为 `{status:1,data:...}`；logo、岗位、待办、收藏、课程 brief 为直接对象或数组。统计天数在原 UI 中仅按标量显示，本地接受 number/string，不声称已验证后端具体类型。

## 路由与生命周期

- `/` → `/login` →（已有会话）`/basic/home`；`/basic` 默认首页；`/activate` 为公共授权入口，未登录不会被误报为未激活。
- `/basic/*` 共用当前用户守卫，不使用工程样例身份授权。未知 403/网络失败显示恢复错误和重试；拒绝访问及未激活分别处理。
- 已知“未登录”403 清理 Query 和 Token，回登录并显示失效提示；“未激活”去激活；“您无权访问”去独立 403 说明页，保留会话。查询和命令均由 API 实例统一处理。
- Query 读取透传 AbortSignal；登录、退出、激活、课程检查、推荐设置和岗位保存由所属页面/弹窗持有 AbortController，卸载取消，取消结果不改变会话或导航。按钮禁用负责普通重复点击，不为按钮增加同步锁或挂载状态。

## usePageSignal 专项评估（2026-10-20）

当前有 12 个消费文件、14 个实例、38 处 `signal.aborted` 判断。hook 的实际生命周期是所属组件的挂载/卸载，并不监听路由；作用是为手写命令请求提供卸载取消信号。Query 读取继续使用 Query 自身的 signal，不能因为查询已由 Query 管理就认为手写提交也自动获得取消。

保留当前 hook：登录、改密、资料保存和上传在请求后会修改会话、全局缓存、导航或 toast，不能只依赖 React 忽略卸载后的 setState。信号用于取消请求，await 后的判断用于阻止迟到副作用，尤其是还需等待缓存刷新的流程。课程切换另有独立控制器，因为同一组件内的新意图不会触发组件卸载。只为局部 setState 增加判断不构成使用它的充分理由，但不能因此删掉现有的会话和导航保护。

取消只能中止客户端等待，不能撤销已被服务端接收的写操作；此 hook 不提供事务回滚或“一次只保留最新提交”的保证。本轮未改写 hook 或增加新的异步框架。定向浏览器回归确认登录离页、头像上传/资料保存/改密离页及切换课程的取消与迟到保护仍生效。

## 原行为差异与后续接点

1. 原“您无权访问”会清用户并跳根，容易混淆登录失效；本地保留会话并显示独立 403。未知 403 不清会话。
2. 原全局取消只在少量调用处出现；本地增加页面级取消，修复离开登录后迟到响应仍跳转的问题。
3. 原推荐、激活失败的动态服务消息改为批准字段或通用文案，避免未经批准的服务细节泄漏。契约错误明确报错，不以空数组或成功兜底。
