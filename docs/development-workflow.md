# 低重复开销实施流程

适用于实施或继续业务切片，以及复盘 token 消耗。目标是减少重复调查、环境启动和上下文输出，保留规格覆盖、必要补证、审查与质量门禁。业务范围和进度仍以 [实施计划](planning/page-rebuild-implementation.md) 为准。

## 默认执行顺序

1. **定向调查**：读取适用规范与当前切片，定位对应 F 条目、现有实现和证据缺口。完成标志是能列清本轮交付、已有结论及真正待查的问题。
2. **短反馈实现**：在已确认的公共测试边界逐个完成行为，复用隔离测试服务；根据变更运行相关测试和类型检查。完成标志是受影响行为通过，而非仅入口存在或文件能导入。
3. **差异审查**：用户或适用技能要求审查时，针对固定 diff 核对规范与规格；修复后复查对应发现。完成标志是发现已关闭，或明确记录尚未解决的阻塞。
4. **定向验收**：按根 AGENTS 的验证规则，只运行本轮改动及直接影响的测试；仅有 UI 改动时运行相关 UI 用例。已通过且未受影响的结果直接复用，不因切片收口启动全量检查。
5. **一次收口**：验收后更新实施计划的切片状态，在实施记录中保存差异和验证结果；功能范围变化时才同步对应台账。仅新增文档变更时检查文档即可；提交按用户授权及适用技能执行。

## 调查与上下文

- 同一轮已经完整读取且未变化的规范、技能直接复用；技能及其必读引用仍按技能规则完整读取。跨会话从文档入口恢复，发生变更或出现矛盾时重新核对相关内容。
- 业务资料按切片读取对应条目和调用链；已有架构文档记录的结论先复用，围绕未解决问题补证。完整技能和规范的必读要求不以“省 token”为由缩减。
- 文件检索先用 `rg` 定位，再读取有界范围。输出截断后缩小到缺失部分，避免再次输出同一批大文件。
- 工具发现只返回候选名称和必要说明；选定后才读取该工具的参数。大型分析优先摘要和证据引用，避免打印整个工具目录或完整类型定义。
- 沿用 spec、ticket 或对话中已确认的测试边界。只有边界改变或授权不明确时再询问，避免重复确认同一个决定。

## 测试与日志

- TDD 的红灯应揭示缺失或错误的公共行为。缺文件、导入失败、命令参数错误只说明环境或接线未就绪，修正后仍需验证行为，不将它们当作充分的红灯证据。
- 专项回归优先复用隔离的本地服务；缺少复用入口时集中运行受影响场景。生产、关闭模拟和自定义 API 等模式仅在本轮改动涉及该模式时定向验证。
- 测试服务保持与原服务隔离，代理和真实写入约束不因复用服务而改变。服务配置不同或已过期时重新启动，不复用未知实例。
- 成功调用只取退出码、测试数量与结论；详细日志留在工具会话或忽略的产物中，失败时定向读取对应错误。预期警告不反复全文输出；退出码和关键失败信息必须保留。
- 单条测试已通过且代码、配置、样本未变化时复用结果。只有对应行为发生变化、审查修复或验证证据不足才重跑，避免每次小修改都启动全套模式。

## 审查、分工与文档

### 表单组件的已确认用法

新增或修改表单时，遵守 [前端 AGENTS.md 的表单格式](../apps/web/AGENTS.md#表单格式新增与修改时必读)，以其中指定的实际组件为例，不在本文重复维护规则。

### 审查与验证开销

- 多个 Playwright 命令不得并发共用默认产物目录，否则会互相清理 trace，造成 `ENOENT` 假失败；顺序执行，或显式隔离 `--output` 和报告路径。
- 仅在用户或适用技能要求分工时使用子代理。提供任务、固定 diff、必要规范/规格入口和证据位置，使用满足任务的最小历史；避免把完整长对话复制给每个审查代理。
- 已完成的前置工作与本轮差异分开审查。工作区有前置未提交改动时先确认提交范围，不把无关变更纳入交付。
- 实施中只在实施计划维护切片状态和必要的新证据；最终验收后补充历史交付记录。功能或证据范围变化时，再同步对应 Markdown、JSON、CSV 与路由台账；这些视图不复制进度。
- 命令、依赖版本和测试配置以仓库文件为准，不在本流程复制整份脚本表。补证结论放对应架构文档，交付结果放实施状态，本文件只保留执行规则和高成本陷阱。

## S02 复盘与已知陷阱

来源：2026-10-19 的 S02 实施，交付提交 `9fa0f35`。以下是调用轨迹复盘，**没有逐调用 token 账单，不能据此给出精确消耗比例**。

| 消耗来源         | 已观察到的问题                                           | 后续处理                                         |
| ---------------- | -------------------------------------------------------- | ------------------------------------------------ |
| 重复读取         | 多份完整资料合并输出，截断后重读；加载了未使用的设计技能 | 先选适用资料，再有界读取，复用同轮已读内容       |
| 工具元数据       | 输出完整工具描述及参数类型，混入大量无关上下文           | 发现阶段只取名称和必要说明                       |
| 环境启动         | 为多次单场景回归反复启动模式测试服务和构建               | 复用隔离服务或集中专项场景，最终统一验证适用模式 |
| 测试与日志       | 部分红灯仅是导入失败；启动日志和构建警告反复返回         | 验证公共行为，成功取摘要，失败取定向详情         |
| 文档收口         | 多份台账先写“待门禁”，随后逐份改“完成”并重复格式化       | 进行中与最终收口分离，最终统一同步               |
| 额外确认与上下文 | 重问已确认的测试边界；审查代理继承完整历史               | 复用确认，给代理最小充分输入                     |

特别注意：[运行模式测试配置](../playwright.modes.config.ts) 使用多服务 `webServer` 数组，**仅用 `--project` 过滤测试，并不会减少启动服务**，其中包含生产构建。S03 新增 [专项配置](../playwright.focused.config.ts)，可用 `pnpm exec playwright test s03.spec.ts --config=playwright.focused.config.ts` 只启动关闭 MSW 的隔离服务；项目、地址与代理隔离策略复用正式配置，不重复维护。执行时换成本轮受影响的测试文件或用例；其他模式按本轮影响选择。

S02 当时的原 bundle 补证与双轴审查发现并修复课程请求竞态、岗位表单方案不符规范、待办年视图缺月份聚合三项问题。历史全量门禁记录不作为后续每轮必须全量执行的要求，当前验证范围以根 AGENTS 为准。

## 上传真实传输专项

S09 的上传字节进度、取消和响应正文生命周期使用真实本地 HTTP 服务，依赖 Vite 源码模块及测试组件入口，独立于正式网盘用户路径测试。运行 `pnpm exec playwright test --config=playwright.upload.config.ts`，仅启动隔离开发服务，不构建生产包。默认开发端口 4193、临时 HTTP 服务端口 4293；端口被占用时可通过 `PLAYWRIGHT_UPLOAD_PORT` 和 `PLAYWRIGHT_UPLOAD_API_PORT` 同时指定一组空闲端口。测试按实际 baseURL 设置 CORS 和 Cookie；开发服务只在此配置中代理到临时 HTTP 服务，退出后关闭连接，不复用未知实例。正式页面上传集成仍由两种业务模式中的 `s09-files.spec.ts` 覆盖。
