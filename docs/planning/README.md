# 学员端功能还原规划

状态：用户已确认功能范围、本机单人运行与技术栈；独立仓库与统一前端骨架已经建立，后续工程能力与业务功能按规格继续实施。

## 已确认的决定

- 最终范围是整个学员端，不能因先做实验台而遗漏其他模块。
- 优先还原业务功能、状态与操作逻辑，样式后续独立翻新。
- 首阶段使用原后端，不重建后端业务与虚拟化基础设施。
- 全部可用交互均属于最终目标，控制台、文件预览、学习进度和流量监控等不能只做入口。
- 教师、管理员端不在重建范围，仅记录发布、分配、配置、评价等上游关联。
- 第一个实现单元是 F001“登录与会话”；完成并验收 F001 后，再沿“我的实验台 → 场景拓扑 → 节点配置 → 保存 → 重开”扩展首条跨功能闭环。
- 不明确的后端操作默认模拟；只读联调须按操作语义白名单，确认测试账号与数据范围后逐项开放真实写入。
- 正常业务规则按原逻辑恢复；明显缺陷修复并记录行为差异。
- 原 bundle 的静态可见功能是复刻事实边界：实现其中可定位的页面、操作、状态分支和请求调用，不新增 bundle 外功能，也不要求通过真实环境补充业务验证。
- 新工程仍执行构建、类型检查和必要自动化测试，用于证明实现自身可工作；这些检查不扩张业务范围，也不宣称验证了当前线上后端。

## 每个功能统一细化格式

每项以F编号建立子条目：

1. 入口：路径、菜单/按钮、深链参数、来源页面、返回位置。
2. 账号与对象：会话、资源所有权、任务分配、共享/只读/锁定、课程/考试/实验状态。
3. 输入：字段名、类型、必填、默认值、长度/范围、联动、枚举来源与错误呈现。
4. 操作：前置条件、请求、重复点击、成功结果、失败结果、后续刷新与撤销边界。
5. 状态：前端加载/空/失败与后台业务状态分开；每个状态对应可用动作。
6. 数据：真实URL表达式、参数编码、方法、CSRF/Token/Cookie、响应、分页、轮询/WS及副作用。
7. 生命周期：刷新恢复、离页未保存、取消请求、定时器/连接清理、多窗口及重连。
8. 验收：正常、空数据、输入错误、无权限、过期/锁定、超时断网、重复操作。
9. 证据：源码位置、R/A/C/V等级、实际账号能力、待验证项、与原行为差异。

适用模板：列表必须核对筛选/排序/分页；编辑页必须核对校验与保存重开；运行页必须核对异步状态和资源释放；学习页必须核对进度与重复提交；文件页必须核对路径、类型、大小和失败恢复。某项不适用要说明原因，不靠默认实现补齐原站规则。

## 核心业务流程与状态约束

### 会话

HTTP认证与应用Token认证分别处理；重建的应用登录不是替代上游HTTP认证。登录后加载当前用户和启用配置。403的“未登录”“您无权访问”“未激活”按原分支处理，同时核对其他状态。禁止将所有403自动当退出登录，也禁止把Token失效继续当成功。

### 实验设计与运行

实验元数据、拓扑设计、运行环境与节点状态分开保存。先编辑设计，再启动运行；运行是否允许改图取决于原始状态和权限，不能根据前端方便自行放开。

节点增删、设备配置、端口连接、坐标/分组保存后重开应一致。跨实验切换清空前一实验的选择、右键菜单、轮询及编辑缓存。保存失败保留用户修改并提示，不能先提示成功。

创建/运行中/已运行/释放中/失败等只作为规划中的语义状态，实际枚举必须从原接口核对，不能硬编码推测值。状态查询、启动、停止、释放、延期和控制台连接分别记录副作用与可执行条件。

### 训练、课程与考试

公开课程、教学任务课程、路线任务课程不能混用进度归属。实操组件虽然复用，也必须保留任务/科目/章节/资源等完整标识。考试与练习使用不同提交契约，不能让练习写入正式考核。

学习开始、视频播放日志、领取任务、提交答案、交卷、Flag/作业及结果状态均可能产生持久变更。计分、次数、期限与结果公布规则由后端和原始证据决定。

### 文件、笔记与实时页面

个人/公开/课程资料按数据域隔离；文件路径与下载地址不当作可随意拼接的本地路径。笔记图片上传、富文本、共享/评分、Word导出分别验收。

控制台、AI流式输出和态势刷新需规划连接状态、过期、重连、取消与离页清理。接上真实服务前使用明确标识的模拟数据，不用模拟结果声称服务已联通。

## 原后端接入规划

- 新前端通过统一适配层访问原接口；保留旧路径、参数、返回值与错误语义，页面只依赖规范化业务对象，为后续换后端留边界。
- 开发时可用同源代理承接HTTP、WebSocket、下载和资源路径；是否可用取决于部署与访问权限，不能预设代理能解决浏览器认证、Cookie或CSRF。
- 原站曾被浏览器工具策略阻止直接访问。该限制仍有效：当前只对用户提供的本地文件分析，不借代理、CDP或其他工具绕过。需要的行为证据由允许的测试环境或用户主动提供的记录补齐。
- 凭据在用户本机输入，不进入代码、规划、fixtures、日志或仓库；真实Token、Cookie和授权头不写入样例。
- 接口目录必须补齐动态前缀与Ae之外的请求：例如Jm拼接的equip_practice、Eb拼接的subject_scene、上传、AI消息与WS。现有536个表达式只是部分候选。
- 方法不等于副作用：原离线课程包删除使用GET，不能“批量GET探测”。按业务操作语义建立读取白名单，默认禁止未知操作。导出、领取、已读、学习日志也要分别分类。
- 状态开关至少区分“本地模拟”“原后端读取”“原后端已批准测试写入”。接口未联通、无权限、被模拟必须能明确辨认。
- 写入放开的前提是指定测试账号、可操作对象、动作范围及清理方式；账号是否已有菜单不等于允许试删真实数据。

## 全站验收与差异管理

- 所有104路由定义都映射为页面/容器/重定向/404；参数和深链刷新可用。
- 49功能组逐一拆分实际适用操作；按钮、表单、条件分支有可追踪条目。
- 账号能力按对象和状态验证；无权限时既不展示错误动作，也尊重后端拒绝。
- 不以静态返回200、按钮可点击、模拟状态或单账号成功代替功能验收。
- 在模拟后端和获准的测试范围完成必要集成测试；考试提交、拓扑保存重开、学习进度、预约冲突、异步生命周期是重点。
- 偏差记录格式：原始证据 → 原行为 → 新行为 → 修改理由 → 受影响条目 → 验证结果。明显缺陷与有意业务规则必须区分。
- 目前不能承诺像素级一致，也不能保证已掌握线上隐藏功能。新证据发现功能时增补F条目，原范围不因先实施其他模块而丢失。
