## 本文件的权威边界

个人资料页的成功提示已一并改为共享 toast，移除该页的 `notice` 状态；验收记录见上方实施记录链接。

同类补齐：待办、诊断样本及拓扑样例的瞬时提示已清理；usePageSignal 经消费方和取消回归核对后保留，未增加异步框架。范围与验证见实施记录。

本文件是页面还原的**实施顺序、依赖关系、切片状态和 F 编号覆盖关系的唯一事实来源**。开始或结束一个实施切片时，必须在同一变更中更新本文件。

- `page-feature-code-map.md` / `.json` 回答“原 bundle 有什么、证据在哪里”。
- `function-catalog.md`、`features.json` / `.csv` 回答“每个 F 编号应覆盖什么”。
- 本文件回答“按什么顺序实现、哪些能力合并实现、何时算完成”。
- `README.md` 中的 P1–P6 仅是产品范围视图，不是开发顺序。
- F001–F049 是穷举覆盖与验收台账，不等同于 49 个独立开发任务。

如新证据改变功能边界，先更新页面—功能对照与功能台账，再调整本文件中的切片映射；不得直接在代码中追加无法追溯到原 bundle 的功能。

## 执行规则

1. 只领取依赖均为“完成”的切片；同批次且依赖满足的切片可以并行。依赖明确细化到已交付子能力时，按本表声明的子能力及其验收证据判断，不要求无关流程一并完成；该细化不能用于宣称前置整片完成。
2. 开始前读取该切片映射的 F 条目、路由及源码证据，不把本文件的摘要当作完整业务规格。
3. 共享能力只实现一次；不同业务域通过显式上下文和适配器接入，不能用多 key 猜测或混用持久化归属。
4. 一个切片必须作为可编译、可测试、可评审的完整单元交付，不提交只有入口、静态壳或模拟成功提示的“完成”状态。
5. 完成时遵守根 AGENTS 的定向验证规则，只运行本轮改动及直接影响的检查；UI 有改动才做相关 UI 验证，不因跨层或收口默认全量。仅修改本文档时只检查格式、链接和覆盖关系。
6. 完成时将切片状态改为“完成”，写明验证命令或证据位置；只有某 F 编号映射的全部切片均完成，该 F 才算完成。功能目录及其结构化视图只维护范围，不复制完成状态。

状态只允许使用：`未开始`、`进行中`、`阻塞`、`完成`。`阻塞`必须写清外部依赖；已实现但未达到完成判据仍是“进行中”。

## 每个切片的统一完成判据

- 映射 F 编号下的全部 bundle 可见路由、操作、状态分支和请求调用均已实现；容器、重定向、深链与 404 按路由台账处理。
- 正常、加载、空、失败、无权限和适用的异步生命周期均有真实 UI 行为；不以静态页面、按钮可点击或模拟返回成功替代功能。
- 请求在统一适配边界归一化；相同语义只有一个字段来源。共享组件保留任务、资源、章节、实验等完整上下文，不串写数据域。
- 覆盖关键可见行为的必要测试通过；类型检查、lint、构建及适用的浏览器检查通过。无需为原 bundle 不存在的能力增加功能或业务验证。
- 本文件维护实际进度；实施记录保存本次范围、验证和差异。只有功能范围或证据改变时才更新对应 F 台账；遗留阻塞和有意差异有明确记录。

F049“全局异常与生命周期”不是独立末尾任务：从 S02 起，上述完成判据对每个切片强制生效，最终再以全量回归收口。

## 进度更新格式

切片开始时将其状态改为“进行中”，并把“下一切片”改为“当前切片”。切片完成时，在对应表格行的交付边界末尾追加：

```text
验证：<命令或证据文件>；差异：<无，或差异记录链接>
```

如切片阻塞，追加：

```text
阻塞：<缺失的外部事实或能力>；已完成：<仍可独立验收的部分>
```

不得用完成百分比替代上述状态和证据。最终完成条件是 S01–S32 全部为“完成”，F001–F049 的映射无遗漏，104 条原始路由定义均在路由覆盖表中具有已实现结论。
