# S06 场景拓扑还原差异修复专项

日期：2026-10-21。覆盖组：F036、F042的S06范围。审查基线：`a35ba40…f4a8345`。

当前实施状态统一见[实施计划](page-rebuild-implementation.md)。本文是一个专项规格，不拆成六个独立专项，不表示已经开始代码修复。发布所需标签：`ready-for-agent`；项目issue tracker尚未配置，本文仅为本地规格，未发布远程issue，标签也未在远程应用。发布前需运行`/setup-matt-pocock-skills`完成项目与标签配置。

## Problem Statement

用户已经能在实验场景拓扑中编辑设备、连接网卡、操作分组、复用节点模板并导出图片，但静态复核发现当前实现还不能称为原bundle功能的等价还原：业务对象成功写入后没有按原触发链保存画布；新增网卡的MAC末节丢零；缺失数组没有原默认行；未渲染旧业务边漏算网卡占用；折线标签偏离线路；新连线默认样式和既有动画未恢复。

这些问题分别影响持久化一致性、配置正确性、合法连线与画布/导出的视觉一致性。此前隔离测试通过没有覆盖这些分支；真实后端是否联动画布或清理未提交对象仍未验证，不应把潜在后果描述为已经发生的数据丢失。

## Solution

以一个专项关闭本次确认的六项差异，保留现有React Flow、API适配与测试体系。先恢复有原证据支持的业务操作后画布保存闭环，再修复配置默认与网卡关系，最后补齐连线标签和默认视觉。

修复后，用户不需要额外点击整图保存来完成原版业务操作的后续画布提交；部分失败有准确提示和针对性重试，不重复创建业务对象。字段、图元和未知关系继续无损保存，已有高清PNG、SVG及权限限制不回退。只有专项验收完成后才能重新声明该范围复刻验收完成。

## User Stories

1. 作为拓扑编辑者，我希望新增设备成功后按原流程保存画布，以便重开后能看到新增设备而不必额外点击保存。
2. 作为拓扑编辑者，我希望保存设备配置后同时完成原流程中的画布提交，以便名称、图标和配置引用保持一致。
3. 作为拓扑编辑者，我希望创建业务链路后完成画布提交，以便新链路及网卡标签能随实验重新打开。
4. 作为拓扑编辑者，我希望显式保存拓扑入口继续可用，以便提交其他尚未持久化的图修改。
5. 作为拓扑编辑者，我希望业务请求失败时不提交伪成功画布，以便知道本次操作尚未完成。
6. 作为拓扑编辑者，我希望业务成功但画布保存失败时保留结果并准确提示，以便有针对性地恢复后续保存。
7. 作为拓扑编辑者，我希望重试画布保存不重复执行已成功的设备或链路创建，以便避免重复业务对象。
8. 作为拓扑编辑者，我希望保存期间产生的新修改仍被标为未保存，以便不把旧快照成功误当作全部修改成功。
9. 作为拓扑编辑者，我希望部分操作成功后离页提示不宣称已撤销远端写入，以便了解放弃本地修改的真实含义。
10. 作为设备配置者，我希望新增网卡时保留原MAC末节补零规则，以便例如末节01之后生成02而不是2。
11. 作为设备配置者，我希望修复只影响新增行的既有算法，以便已有MAC及其他未知网卡字段不被重新格式化。
12. 作为设备配置者，我希望合法缺失的普通数组恢复原有默认行，以便原字段默认值不因打开表单而消失。
13. 作为设备配置者，我希望缺少数量定义的网卡数组仍按原规则初始化，以便获得原入口的初始配置。
14. 作为设备配置者，我希望已有合法空数组和显式数量定义保持其语义，以便默认恢复不覆盖用户已有配置。
15. 作为设备配置者，我希望损坏的已有结构继续明确报错，以便不以默认值掩盖错误数据。
16. 作为拓扑编辑者，我希望无法渲染但仍保留的旧业务边参与网卡占用检查，以便不能把同一网卡再次连接。
17. 作为拓扑编辑者，我希望表单选项和提交前校验使用一致的完整关系，以便不出现可选但提交逻辑不一致的端口。
18. 作为拓扑编辑者，我希望处理未知边时原字段仍被保存，以便修复占用判断不会隐式删除旧链路。
19. 作为拓扑查看者，我希望正交折线和含折点线路的网卡文字沿实际路径定位，以便明确识别连接两端。
20. 作为拓扑查看者，我希望移动、缩放、旋转端点后标签仍贴合线路，以便复杂图中标签不悬空。
21. 作为拓扑编辑者，我希望新建业务连线采用原默认蓝色虚线与流动效果，以便默认视觉语义一致。
22. 作为拓扑查看者，我希望已保存线路的受支持样式和动画正确显示，以便不是只保留字段却不渲染。
23. 作为导出使用者，我希望PNG/SVG保持修正后的线路、标签和背景，以便下载结果与画布一致且PNG仍清晰。
24. 作为只读或锁定拓扑的查看者，我希望本专项不开放任何额外业务写入口，以便既有权限边界不被修复绕过。
25. 作为工程协作者，我希望六项问题都有针对性回归和明确证据，以便区分静态还原、隔离验收与真实后端联调。

## Implementation Decisions

- 本专项只处理六项确认差异，不借机重写编辑器、替换库、修改后端协议或引入通用工作流框架。每项均须以原bundle的可达调用链和当前公开行为为依据。
- R01／P1：恢复原调用链已经证明的业务操作后整图提交，至少覆盖新增设备、保存设备配置、创建业务链路。实施时核对相邻编辑、删除等已知保存调用点，属于同一持久化差异的遗漏一并修正；不推导为每次键入、每个拖动事件都全局自动保存。
- 沿用统一业务客户端和图适配边界。设备/链路业务写入成功与整图保存成功是两个独立结果，后者成功才推进对应图快照基线及该批资源追踪。原先保留的显式整图保存入口继续存在。
- 同一操作在业务阶段成功、整图阶段失败后，应保留已创建对象、画布草稿和待保存状态；重试只补未完成阶段。不得以自动重试创建、自动删除远端对象或宣称事务回滚补偿错误。复用现有在途/快照机制，不新增持久化任务队列。
- 请求期间的新编辑不被已提交快照吞掉；离页/刷新保护覆盖未完成操作，取消不冒称撤销已发生的远端写入。资源归属始终使用当前实验的拓扑标识，不混用画布UUID、业务行ID和模板资源ID。
- R02／P2：新增网卡沿原十进制末节加一规则处理小于10的补零，修复01到02变成2的偏差。不得扩展为新的十六进制MAC分配器或改写用户已有MAC；原算法的其他局限不在本专项修正。
- R03／P2：在配置适配边界恢复原缺省数组规则。普通数组缺失时默认一行；网卡数组按原数量定义分支初始化，没有数量定义时一行；行内字段使用原schema默认。合法已有数组，包括空数组，不被无条件补行；显式数量定义遵循原分支，不靠通用兜底猜数量。对象/数组类型损坏仍明确拒绝，不用默认值吞错。
- R04／P2：网卡可用性同时考虑可渲染边及原样保留的旧业务边。选项禁用、提交前检查与已有网卡删除保护基于一致的业务关系，不把“端口磁吸点失效”误当作“业务NIC未占用”。保留NIC索引0有效、纯图边不占业务NIC、允许不同NIC间多重连线的原规则。
- R05／P2：网卡标签使用实际绘制路径的长度比例定位，覆盖直线、正交路由与已有折点；保持原标签位置比例及文字。路径变化和视图变换后重算，避免仅按起终点连线插值；不新增折点编辑器或第二套线路渲染引擎。
- R06／P2：新业务连线补齐已确认默认蓝色、虚线参数和流动效果，已有受支持线样式和动画进入实际渲染。不能用默认值覆盖已有自定义颜色/线宽/虚线；动态运行状态颜色仍属于后续切片。PNG是静态快照，不要求输出动画文件。
- 保留现有锁定、共享/只读限制与节点模板分阶段重试；保留未知图元/字段、父子关系及三倍分辨率PNG和原SVG导出。分组、复制业务对象等未受影响实现不为追求原缺陷而回退。

## Testing Decisions

- 用户已确认沿用现有S06测试边界：优先使用隔离浏览器完整行为流程，仅配置默认值和无效磁吸点关系补现有纯函数回归，不新增测试框架或生产测试入口。
- 好测试观察用户操作、实际HTTP请求/结果、状态提示、重新GET后的图以及下载产物，不断言组件私有state，不复刻实现算法来证明实现正确。服务保留已接收的业务对象和图，模拟服务不会替应用自动同步或修复draw。
- R01：分别覆盖设备创建、配置更新、链路创建后业务请求到整图请求的顺序及内容；不额外点击保存即可重新GET/重开验证。覆盖业务失败、业务成功后draw失败、仅重试draw、重复点击、保存期间新编辑和离页保护。计数证明不重复POST/PATCH业务对象；锁定与只读不得发写请求。
- R02：浏览器在真实表单操作新增网卡，检查显示和实际提交体中的补零MAC，同时核对旧行与未知字段保留。
- R03：在现有API配置适配测试验证缺失普通数组、缺失ports且无数量定义、显式数量定义、已有空数组、已有行和损坏结构；再以受影响表单流程检查默认行可见并实际进入提交，保留engin10禁增删规则。
- R04：在现有图适配/关系测试构造磁吸点失效而NIC索引仍有效的旧业务边；浏览器确认对应NIC不能再次选择/提交、旧边仍保存，未占用NIC可连接。覆盖索引0、两端占用、纯图边和不同NIC多重边，不将只有可渲染边的样例当作覆盖完成。
- R05：用偏移端点与非共线折点制造直线插值必错场景，从实际线路/标签DOM几何验证标签沿线；覆盖正交、已有折点、节点移动及视图缩放。保存重开后结果一致，不能只检查标签文本存在。
- R06：验证新建和重开后的默认颜色/虚线及动画确实生效，自定义样式不被覆盖。沿用PNG/SVG下载解码和像素检查，核对标签背景、线路与图标，PNG保持三倍尺寸；截图只作为补充，不替代行为和产物断言。
- 复用现有S06资源/配置/保存、画布工具与模板导出场景作为先例；只运行新增或直接受影响的用例、最小web类型检查及改动文件lint/格式。文档规格阶段只检查文档，不运行全量测试、构建或浏览器。
- 修复前先得到能够捕捉本问题的红灯，修复后在同一边界转绿。验收记录区分静态证据、隔离HTTP模拟与获准真实验证；当前未授权任何真实业务写入。Browser插件不可用时沿用项目Playwright并如实记录。

## Out of Scope

- 实施本专项代码、拆分工单或启动其他切片不属于本次规格编写交付；须在后续实施任务执行。
- S07的环境启动/释放、运行状态、VNC/KVM/控制台；S08的流量监控、模拟与镜像。
- 当前入口不可达的完整拓扑模板、分块拓扑模板、拓扑文件导入，以及把PNG/SVG作为可恢复配置协议。
- 原版美术资产的像素级复刻、整体布局重设计、仅因文件长而做的大规模拆分、技术栈替换、依赖升级或新的状态框架。
- 自动回滚真实业务写入、远端对象清理、后端事务/接口修改、未获授权的真实创建/修改/删除；不猜测后端对draw的联动行为。
- 对所有原bundle入口作无遗漏保证。此次验收只关闭六项确认差异及其直接影响，不把静态验证提升为当前线上全功能验收。
