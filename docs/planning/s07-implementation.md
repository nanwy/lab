## 票01：实验场景与节点生命周期（2026-10-21）

复用 S06 正式实验拓扑页、节点菜单、统一 API 客户端、Query 和离页保护；没有重建画布、预建通用运行框架、添加延期或自动重试。业务实现约350行，未增加依赖。

### 行为与契约

- 实验继续使用唯一的 topo_id 和 task_type=6。状态 GET `/front/topo/{id}/status/?task_type=6`，nodes 按画布 UUID、edges 按业务行 data_id 显示；0–6 分别为未启动、启动中、启动成功、启动失败、关机、上传镜像中、暂停。
- 单节点启动/释放/重启/关机均 POST `/front/topo/{id}/node/{uuid}/{action}/?task_type=6`，body 为 `{}`。批量启动为 POST `/front/topo/{id}/node/start/?task_type=6`，释放为同 URL 的 DELETE，body 为 node_list UUID 数组。整图启动/释放 POST `/front/topo/{id}/{start|stop}/?task_type=6`，不添加请求体；所有变更以 status=1 判成功，失败复用统一 API 提示。
- 菜单按原节点状态和设备类型开放，保留锁图可运行、共享隐藏整图工具栏但允许适用节点动作、readOnly 禁止操作的差别，不从实验详情猜测权限字段。批量过滤分组和标注。保留“节点释放后会删除相关数据”的提示。
- Query 是运行事实的唯一来源，状态与链路着色只用于显示，不进入 X6 设计草稿、保存基线或连线配置。操作后重读状态；不引入自动轮询、后台作业跟踪或恢复机制。手动刷新和重新进入恢复服务端状态。
- 开启/关闭错误信息面板，列出 status=3 的节点/链路及错误，按更新时间倒序。运行过程中显示对应动作提示；运行、保存和冲突操作互斥，同步 ref 防止重复提交。
- Query 的 AbortSignal 取消旧状态请求；运行写入使用组件生命周期的 AbortController。沿既有离页提示允许用户离开，取消前端等待、忽略迟到结果，不因此发送远端释放请求。取消等待不代表撤销已发送的远端操作。

状态刷新保留设计草稿是本轮明确要求；没有沿原启动/释放后的整图重读覆盖当前编辑。原失败分支在本地直接设 status=3，本实现保留已读取状态并显示服务错误，避免用失败响应捏造新的服务端状态。

节点快照/镜像/NAT等运行资源、VNC/RDP/字符终端和操作机留在后续三票；场景 model=topo 不新增延期，未来学习/考核环境消费者仍归对应切片。
