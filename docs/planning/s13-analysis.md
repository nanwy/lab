## 入口、上下文与边界

`R089 → _8s @ 12737090 → e_t @ 9923948`。实验入口传 `module="1"`、`module_id=experiment.id`、`test_task_id=experiment.test_task`；导入回调重新请求实验详情。实验 ID 缺失时显示“请重新点击进入实验”。

| 标识        | 来源与用途                                             | 禁止的替代方式                       |
| ----------- | ------------------------------------------------------ | ------------------------------------ |
| 实验 ID     | `experiment.id`；实验域蓝军列表、导入                  | 不把它当作所有运行请求的任务 ID      |
| 测试任务 ID | `experiment.test_task`；初始态势、运行、过程和结果     | 不用 `topo_id` 或 `task_type=6` 替代 |
| 蓝军实例 ID | 实验蓝军列表选中项 `id`                                | 不用剧本 ID 或智能蓝军 ID 替代       |
| 剧本 ID     | 选中项 `scenario`；详情、剧本图、终端                  | 不用蓝军实例 ID 替代                 |
| 智能蓝军 ID | 选中项 `intelligent`；智能配置详情                     | 不猜多 key 兼容                      |
| 轮次 ID     | `control_record` 行的 `id`；参数名 `blue_team_control` | 不用显示序号 `round` 替代            |

原通用运行组件写作 `test_task_id || module_id`，但实验入口的两个标识具有不同语义；缺任务 ID 的处理必须明确报错或显示不可运行状态，不能把这个兜底推广成已确认契约。现有 `apps/web/src/api/experiments.ts` 的详情模型没有 `test_task`，实施需补适配；`router.tsx` 的 simulate 仍为占位。S07 的拓扑运行 API 固定 `task_type=6`，只复用请求、会话和已确认的公共能力，不复用其业务路径。

`e_t` 在实验域提供三页：蓝军配置、初始态势、运行控制。运行控制下有蓝军控制、执行过程、决策过程、蓝军数据四项；默认选第一项，选择不同蓝军后重置到蓝军控制。蓝军列表读取 `?nopage=1`，无选中项时取首项；无蓝军时显示导入入口；卸载或切 module/module_id 时清理 `tv` store。

S13 包含原 simulate 可达的内嵌初始态势、决策图和蓝军数据。S14 继续负责 R098–R100 的独立蓝军、防御、导调态势。`e_t` 虽有 `v==="5" → Jfo` 和 `v==="6"` 分支，但菜单只有 key 1–4，不能据死分支扩张 S13。共享组件的 module 2–6 调用方属于后续业务切片，不在本轮实现其入口。

## 运行、检查、轮次接口

下表路径前缀 `B=/api/front/wqzb/test_task/{taskId}/blue_team/{blueId}`。方法、参数与成功判据来自原包装函数和消费 store；均未向真实服务调用。

| 操作         | 方法与路径                                 | 参数/响应消费及后续行为                                                                                                             |
| ------------ | ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| 读取控制状态 | GET `B/control/`                           | `I2n @ 1814147`；`status===1` 取 `data`，消费 `status`、`executed_time`；执行视图还消费当前决策信息                                 |
| 执行控制     | POST `B/control/`                          | `N2n @ 1814230`；body `{action}`，值为 `start/pause/continue/over/clear`；`status===1` 后重读状态及当前页轮次，关闭清空确认         |
| 检查         | GET `B/stage_check/`                       | `O2n`；query `kind=1/2/3`，一键检查不指定 kind；只有 `status===1 && message==="检查通过"` 才标记对应检查通过，其余 message 为未通过 |
| 轮次列表     | GET `B/control_record/`                    | `L2n @ 1815975`；控制页 `{page:1,size:5}`，消费 `{count,results}`；过程/数据页 `{nopage:0}`，消费数组。不能统一强制一种响应形状     |
| 删除轮次     | DELETE `B/control_record/{roundId}/`       | `wQr @ 1816077`；`status===1`；当前页唯一行且 page>1 时减一页，重读列表                                                             |
| 发起对比     | POST `B/control_record/compare/{roundId}/` | `SQr`；无显式 body；`status===1` 提示对比完成并刷新轮次                                                                             |
| 读取对比     | GET 同上                                   | `CQr`；query `{page:1,size:10}`；消费 `{count,results}`；选轮次后页码重置                                                           |

原状态门控：控制状态 `0/4` 显示启动和清空，`1/2` 显示暂停或继续、结束、清空；`1` 对应暂停按钮，`2` 对应继续按钮。三项检查标签来自前端检查结果 `cut_in/emplaced/entering`；原按钮没有“三项全通过才准启动”的前端门控，不能自行添加。module=4 才有通过外部运行信息填 `scene_id` 的分支，实验 module=1 不发送该字段。

轮次状态：`0 初始化 / 1 执行中 / 2 暂停中 / 4 已结束 / 5 对比中`。仅 `status===4 && round!==1` 可点对比；`status===5` 显示查看。删除有确认框，清空另有“清空所有轮次数据”的确认框。列表消费 `id,round,status,start_time,end_time`；执行时长由起止时间计算。对比结果消费 `id,sub_technology_name,undefended_return,defended_return,conclusion`；详情展示两侧 JSON；`conclusion==="内容一致"` 显示原防御效果说明。

原控制页在当前页首行 `status===1` 时以 5 秒延迟刷新轮次，否则刷新控制状态；不能笼统写成所有页面每 5 秒轮询。`lho` 按 `executed_time` 每秒增加显示计时，卸载清 interval。

网络视图将 `ip_relation` 转成 IP/交换机/路由器图；点击 IP 从 `input_ip_params_map[ip]` 展示节点 JSON，没有采集值时提示“当前节点未采集到数据”。数据视图有刷新、新增、右键新增子数据/编辑/删除，删除提示包含子节点；底部执行记录可以收起、分页。这些都属于原可达功能，不因名称为“数据”而改成只读。
