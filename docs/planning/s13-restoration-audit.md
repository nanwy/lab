## 功能一致性审查

### P2：决策环缺少原默认下钻与返回父层

位置：[DecisionGraph.tsx:183](../../apps/web/src/blue-team/DecisionGraph.tsx#L183)。当前 `DecisionSunburst` 只有 SVG 扇区、标签和 title，没有视图根节点或点击处理，点击深层扇区不会展开该子树，也不能返回父层。

原 `bho`（`9739000` 前的窗口）使用 ECharts sunburst，未禁用 `nodeClick`。虽然业务层注册的 click 回调为空，bundle 内 sunburst 默认配置在 `4852436` 为 `nodeClick:"rootToNode"`；内部处理器 `4850396–4850735` 仍执行 `_rootToNode`，中心 virtualPiece 点击则返回父节点。之前仅检查业务回调，遗漏了图表库默认行为。

最小修复：恢复子树下钻和父层返回；不添加平移、滚轮缩放或新分析接口。

### P2：历史日志失败会挡住已收到的实时日志

位置：[ExecutionProcess.tsx:327](../../apps/web/src/blue-team/ExecutionProcess.tsx#L327)。组件先判断历史日志的 pending/error，再考虑 `events`。当 `control/log/` 失败或尚未完成，即使 WS 已收到 kind=1 日志并更新状态，页面仍只显示加载/失败，实时日志不可见。

原 `hho @9722645` 的历史读取只在成功时设置日志，WS 独立向日志数组前插，渲染不受历史请求失败阻断。最小修复是独立展示已有实时日志，同时保留历史请求失败反馈。应定向验证“历史请求失败后收到 kind=1”这一分支。

### P2：态势叶节点的空子树语义被收窄

位置：[blue-situation.ts:42](../../apps/web/src/api/blue-situation.ts#L42)。`child` 只接受数组或缺省，拒绝 null；任一叶节点为 `child:null` 会使初始态势或蓝军数据整份响应解析失败。

原 `rho @9700217` 使用 `i.child&&i.child.length>0`，可处理 null 子树。最小修复是在适配边界接受明确的空值并归一化为空数组；非数组的错误类型仍应拒绝。此结论证明原前端可接受该结构，未宣称真实后端已返回 null。

### P2：能力详情的空参数语义被收窄

位置：[blue-script.ts:292](../../apps/web/src/api/blue-script.ts#L292)、[blue-script.ts:304](../../apps/web/src/api/blue-script.ts#L304)。`input_params/output_params` 以及参数递归 `child` 只接受缺省，不接受 null，导致详情整体读取失败。影响剧本动作参数详情与智能蓝军技战术能力详情。

原 `Ggo @9893692` 附近使用 `input_params||[]`、`output_params||[]`（`9895900`窗口）和 `child?.length`；原 `_go @9832800` 附近也按参数列表可空展示“暂无”。最小修复只恢复这些已有空值语义，不增加猜测字段或多 key 兼容。

### P3：关系图布局采用了近似实现

原态势 `VZn @9756663` 使用 `layout:"force"`、可漫游和拖拽；[InitialSituation.tsx:90](../../apps/web/src/blue-team/InitialSituation.tsx#L90) 按 depth/row 固定排列，蓝军数据复用此图。原网络 `Vit @5737671` 同样为力导向布局；[BlueNetwork.tsx:129](../../apps/web/src/blue-team/BlueNetwork.tsx#L129) 改为固定三列。

节点、关系、详情和维护操作仍有实现，不能称为整项功能缺失；但复杂关系的自动布局没有严格还原，应作为呈现差异保留。态势节点拖拽原本存在，不属于新增设计。
