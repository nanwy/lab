## Spec：确认的行为偏差

### 1. P2：目录重读失败卸载已有学习内容

位置：`apps/web/src/courses/CourseDetailPage.tsx:74`。

`courseSections(catalog.isError ? [] : (catalog.data ?? []))` 在刷新失败时抛弃仍然缓存的成功数据，`section` 随之变成空值。点击视频节后播放次数请求成功会触发目录重读；若该重读失败，已有视频、测试和笔记等依赖 `section` 的子树被卸载。自动重连引起的目录重读失败也可影响正在运行的实验。视频未提交的分片缓存、笔记草稿和环境自动释放倒计时因此可能丢失或停止；远端环境并不会因本地卸载自动释放。

原 `bF.taskCourseCatalog`（查询窗口 @2457400）只在获得数组时更新目录，失败不清空已有数据。第四票内部已处理的“重读失败保留环境面板”没有覆盖这个更上层的宿主。

最小修正：已有目录继续派生当前节，错误提示独立显示；首次无数据失败仍显示错误。补一个“已有内容 → 目录重读失败”的针对性回归，不需新增状态管理层。

### 2. P2：实验章节选择缺少原有目录刷新

位置：`apps/web/src/courses/CourseDetailPage.tsx:89–96`。

当前目录 `refetch()` 放在 `s.type === 1` 分支中，实验节点击只切换本地选择。原 HEi 的 `U`（查询窗口 @3604100）是视频节先增加播放次数，随后所有章节都调用 `s({id:p,type:1})` 刷新目录。

完成实验后切换或重新选择实验节，当前实现可能继续显示旧的完成标识/进度，直到无关的自动刷新或重新进入页面。检查点成功后重读检查点不能替代课程目录刷新。

最小修正：把目录重读放回两种章节共用的选择路径，保留视频节先增加播放次数的顺序；不增加完成接口或本地计分。

### 3. P2：视频末尾缓冲卡顿遗漏恢复动作

位置：`apps/web/src/courses/CourseVideo.tsx:150–158`。

当前将 `play()`、提示和延后 `startLoad()/recoverMediaError()` 都放在 `currentTime + 1 < duration` 内。最后不足一秒时发生 `BUFFER_STALLED_ERROR`，整段恢复动作均不执行；duration 尚不可比较时同样如此。

原 HEi ERROR 回调（查询窗口 @3600400）只用此条件限制向前跳一秒，继续播放及延后恢复在条件外执行。缺失恢复可能让临近结束的播放卡住，进而无法触发结束上报。

本轮直接提取当前源码 ERROR 回调，用桩视频执行：duration=100、currentTime=50 时记录 play/warning/startLoad/recoverMediaError；currentTime=99.5 时记录为空。此为回调逻辑验证，不是实际浏览器或真实媒体验收。

最小修正：只有修改 currentTime 保留边界条件，恢复调用移至条件外；沿用现有冷却和可清理定时器。

## 已知缺口与不计遗漏的分支

- **U01：批量导出未完成。** `CourseMaterials.tsx:197` 明确禁用。原客户端仅提供 download_url/url/string 猜测式处理，无法建立唯一契约；不能以另一端点的响应补猜。需要课程导出独立协议或脱敏真实响应。
- **U02：对抗检查、防御上传仍不可用。** `CoursePractice.tsx:236–246` 明确禁用并解释原因。原 BEi/PEi 没传 submitCheck/checkUrl；这是原课程缺链，不能借其它业务接口假装恢复。
- **U03：原生 HLS 没有等价分片日志链。** 当前保留原分支限制；共享环境查询/启动的 share 来源差异也按原保留。不能宣称跨浏览器日志和共享语义已验证。
- 原购买按钮没有有效课程回调，当前明确不可用；未发现可还原的购买协议。
- 截图笔记、模板导入只有定义/挂载而未观察到公开课触发入口；不算本次遗漏。旧 self_test 包装、操作项目选择器、额外操作机、自动续播、离页补报也不应新增。
- Schema 的真实字段类型、必填性和空值仍需要脱敏响应验证；静态消费与自造样例不能证明全部真实响应兼容。例如无 name 的 libvirt 节点当前被允许解析，但生成路由的 name 段可能为空，应在真实节点取样或独立路由验证时检查，尚不列为已证实业务缺陷。
